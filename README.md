# ButtoBuster（ブットバスター）

敵を剣で吹き飛ばし、壁に叩きつけて場外へ飛ばす 1 人用の 3D アクションゲームです。
Unity のコンポーネント指向の仕組みを C++ と DxLib で自作したエンジンの上に、ゲームを組み立てています。

## 紹介動画

（YouTube の URL）

自作エンジン → ゲームの遊び方 → 工夫した 4 つ（敵 AI・ステートパターン・オブザーバー・画像を 3D に置く）の順に、約 3 分で紹介しています。

## 見てほしいところ

### 1. 自作エンジン（`Source/Engine/`）

Unity と同じ名前・同じ継承の並び（Object → Component → Behaviour → MonoBehaviour）で作り、Unity で書き慣れた形（部品を足し、Start と Update を書く）を C++ でそのまま書けるようにしました。

| 部分 | ファイル | 見てほしいところ |
|---|---|---|
| Component | `Core/GameObject.h` `Core/Component.h` | 部品を unique_ptr で持ち、型をキーにした表にも登録する。GetComponent はその表を引くだけ。部品は付けた順に Update される |
| Quaternion・親子 | `Core/Quaternion.h` `Core/Transform.h` | 位置と向きは読むたびに親をたどって計算する（向き ＝ 親の回転 × 自分の回転） |
| 骨に付ける | `Animation/BoneFollower.h` | 剣は手の骨を写す入れ物の子。骨の値はもう世界での値なので、入れ物は親の変換を無視し、回転が二重にかからないようにした |
| Collider | `Physics/Collider.h` `Physics/PhysicsManager.cpp` | Collider は Component を継承。PhysicsManager が毎フレーム「動かす → 地形と当てる → 体どうし → 知らせる」の順に処理する |
| 音 | `Audio/SoundManager.h` | 「フォルダ/名前」で音を引き、使い回す AudioSource（SE 20・BGM 2）で鳴らす |
| アニメーション | `Animation/Animator.h` | キャラが渡す時間で進め、前のフレームとの間に入ったイベント（足音・振りの音）を呼ぶ |
| 描画 | `Render/RenderManager.cpp` | 不透明 → 半透明の順に並べてから描く（Unity の Render Queue と同じ考え方） |
| 1 フレーム | `Core/System.cpp` | 入力 → 物理 → Update → カメラ・空 → 音 → 描画 → 画面に出す → 破棄。消す物は印を付けて止め、フレームの最後にまとめて消す |

Engine/ は Game/ を一切 include しません（依存は Game → Engine の一方通行）。最初のシーンもゲーム側から渡すので、エンジンはほかのゲームにも使えます。

### 2. 敵 AI：ビヘイビアツリーと「賢さ」

- `Engine/AI/BehaviorTree.h`：UE のビヘイビアツリーを参考に、Selector・Sequence・Condition・Action の 4 つの部品を C++ のテンプレートで自作
- `Game/Enemy/EnemyAI.cpp` の `BuildTree`：上の行ほど優先。割り込みたい行動は上に 1 行足す
- 枝ごとに必要な賢さ（1〜5）を決め、足りない枝は木に入れない。難易度は賢さの足し引き

### 3. ステートパターン（`Source/Game/State/`、`Game/Player/State/`）

- 1 つの行動を 1 つのクラスに（プレイヤー 13、敵 7）。入る・毎フレーム・抜けるを 1 つのクラスにまとめる
- `StateManager.h`：切り替えを予約し、今の状態の処理が終わってから行う

### 4. オブザーバーパターン（`Engine/Core/Observer.h`、`Game/Player/PlayerFactory.cpp`）

- 大きな演出は「起きたこと」を知らせるだけにし、エフェクト・SE・UI は受け取る側が出す
- 受け取る側をつなぐのは組み立てる場所（PlayerFactory など）の 1 行

### 5. 2D の画像を 3D に置く

- `Game/Effect/MarkerRenderer.cpp`：足元の輪を 4×4 のマスに分け、角 25 か所の真下の地面の高さに置いて、でこぼこの地面に沿わせる
- `Game/Effect/SpriteEffectRenderer.cpp`：雷のイラストの板を、縦はまっすぐのまま横だけカメラへ回す

## 意識したところ

- **仕様が変わっても、足す・消すがしやすい作り方をする**
  敵やプレイヤーの行動は「1 行で足す枝」や「1 つのクラス」にし、演出は受け取る側を足すだけで済むようにしました。
- **調整する数値は表 1 か所にまとめる**
  難易度は `Game/Phase/Difficulty.cpp`、演出の数値は各 Observer の先頭の表など、調整するときに見る場所を 1 か所にしています。
- **バグやプレイの違和感を、自分で調べやすい仕組みを作る**
  F1 のデバッグメニューから、当たり判定の表示・無敵・状態の表示・敵を出す、などをすぐ切り替えられるようにしました（下の「デバッグ用のキー」）。
- **初めての人でも遊べる 3D アクションにする**
  自分の母でも遊べるくらいの 3D アクションにしたかったので、敵が一度に攻めてくる数を「攻撃の番」で絞りました。集まると溜め攻撃や空中からの叩きつけのような範囲攻撃で簡単になってしまうこと、初心者は一気にたくさん来ると焦ってしまうことも理由です。
- **数値をいじるより、行動で強さを変える**
  if 文の EnemyAI のころは、数値を緩めても結局そんなに強くも弱くもならず、行動も単一で面白くありませんでした。数値を過度にいじるのもしたくなかったので、使える行動そのものを変える「賢さ」を作りました。
- **必殺技の雷はできるだけ立体に見せる**
  雷はイラストですが、必殺技に使う大事な部分なので、横から回り込んでも細い線にならないようにしました。

## ゲームの決まり

| 決まり | 中身 |
|---|---|
| 吹っ飛ばされ値 | HP の代わり。攻撃を受けるたびに溜まり、溜まるほど遠くへ飛ぶ。数字は出さず、湯気と体の赤みで見せる |
| 壁割り | 吹っ飛ばされ値が許容値に届いた状態で、勢いよく（壁へ向かう速さ 300 以上）壁に当たると、壁を割って場外へ。敵なら撃破、自分なら負け |
| 壁バウンド | 許容値に届いていなければ、壁に一瞬張り付いて跳ね返る。速さ 300 未満なら壁際で止まる |
| 連鎖 | 吹き飛んだ敵が砲弾になり、触れた敵も巻き込んで吹き飛ばす |
| ジャスト回避 | 当たる直前の回避で敵がスローになり、踏み込んで反撃できる |
| 必殺技 | 連鎖や壁割りでゲージが溜まると、場の敵全員に雷を落とせる |
| フェーズ | 敵を全部倒すと次へ。フェーズ 10 を越えたら勝ち。全回復の間隔は難易度で変わる |
| 難易度 | EASY / NORMAL / HARD。敵の賢さ、自分の許容値、同時に攻撃してくる敵の数、全回復の間隔が変わる。最高記録も難易度ごと |

流れは、タイトル → 難易度を選ぶ → チュートリアル（飛ばせる） → 本番 です。

## 動かし方

1. DxLib（VisualC++ 用）を `C:\DxLib_VC` に置く（`C:\DxLib_VC\プロジェクトに追加すべきファイル_VC用` を参照しています）
2. `ButtoBuster/ButtoBuster.sln` を Visual Studio 2022 で開く
3. 構成を `Debug | x64` か `Release | x64` にしてビルド・実行する

## 設計の考え方

「よく変えたくなる所」を先に考え、そこを役割ごとに分けました。

| 役割 | 使ったもの | 変えやすくしたいこと |
|---|---|---|
| 敵の行動 | ビヘイビアツリー + 賢さ | 敵の行動を 1 行で足す・差し替える。難易度で敵の賢さを変える |
| 状態 | ステートパターン | 技や状態を足す。1 つの状態だけを直す。チームで作業を分ける |
| 演出 | オブザーバー | 音・光・文字を作り直す。チュートリアルなど受け取る側を足す |

### 敵 AI：ビヘイビアツリーと「賢さ」（Engine/AI/BehaviorTree.h、Game/Enemy/EnemyAI.cpp）

- Selector が上の枝から条件を見て、最初にそろった行動を選ぶ。毎フレーム選び直すので、移り先を書かずに行動が切り替わる
- Condition には const のメンバー関数しか渡せない形にして、「見るだけで値を変えない」をコンパイラに守らせる
- 枝ごとに必要な賢さ（1〜5）を決め、足りない枝は木に入れない
- 難易度で敵の賢さを足し引きする（EASY −1 / NORMAL ±0 / HARD +2）。敵のデータは種類ごとに 1 つのまま
- ほかに難易度で変えるのは、自分の許容値・同時に攻撃してくる数・全回復の間隔。EASY は敵の攻撃の待ちも 1.6 倍（最後の調整）
- 同時に攻撃してくる数（攻撃の番）は、序盤は 1 体で、フェーズが進むと増える（上限は EASY 3・NORMAL 4・HARD 5）
- 難易度の表（Difficulty.cpp）は static_assert で数のずれをビルド時に止める

### 状態：ステートパターン（Game/State/）

- 1 つの行動を 1 つのクラスに（プレイヤー 13、敵 7）。入る・毎フレーム・抜けるの形は ICharacterState&lt;T&gt;
- StateManager&lt;T&gt; は切り替えを予約し、今の状態の処理が終わってから行う。同じフレームは先に来た要求を採る
- 技を始める判断は PlayerActions に 1 か所でまとめる
- 状態のメモリは StatePool で大きさごとに使い回す

### 演出：オブザーバー（Engine/Core/Observer.h）

- 大きな演出は「起きたこと」を知らせるだけ。音・エフェクト・文字は受け取る側が出す（知らせ 6 種類、受け取る側 15 個：エフェクト 6・SE 5・UI 2・ゲージ 1・チュートリアル 1）
- 知らせる側と受け取る側はお互いを覚え、先に消えた方が相手から自分を外す
- 演出の数値は各 Observer の先頭の表にまとめる（例：WallBreakEffectObserver の ENEMY_LOOK / PLAYER_LOOK）
- 被弾の火花など決まった反応は、追いやすさを優先して直接書く

## そのほかの設計

| パターン | 使った場所 | なぜ使ったか |
|---|---|---|
| コンポーネント | GameObject + Component | 機能を部品として足し引きする |
| データ駆動 | AttackData / EnemyData / PhaseData / DifficultyData / TutorialSteps | 技や敵の違いは表で表し、処理は 1 つにする |
| ファクトリ / ビルダー | PlayerFactory / EnemyFactory / CharacterBuilder | キャラの組み立て手順を 1 か所にまとめる |
| オブジェクトプール | NeedlePool | 針を先に作って使い回す |
| 共有の寿命 | BlowChain（shared_ptr） | 連鎖に関わる全員で持ち、最後の 1 人が手放したら終わる |
| トークン | AttackTokenPool | 同時に攻撃してくる敵の数を限る |
